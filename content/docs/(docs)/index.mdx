Welcome to the IT Chapter's system documentation!

Here, you can find documentation for the various systems built for and by the IT Chapter.
All systems might not be documented yet, so if something is missing, feel free to contact [init](https://init.kth.it).

## Goals

The purpose of this documentation site is to provide a comprehensive overview of the IT Chapter's systems and
their respective functionalities. It also reduces the dependency on old students, ensuring the longevity of
the systems and reducing duplicate work.

## Contributing

All chapter members are more than welcome to contribute to the various systems we develop and maintain.
Software development is fun, and we encourage everyone to get involved.

### Projects

Every project has different needs and requirements, so please consult
the repository's `CONTRIBUTING.md` if there is one.
If not, do not hesitate to ask someone in [init](https://init.kth.it).

Every project _should_ have someone who is head responsible for it's development and maintenance.
Once again, if this is not the case, please contact [init](https://init.kth.it).

We should always aim to keep all projects open source under a [permissive license](https://choosealicense.com/licenses/mit/)
as to give back to the open source community.

### Documentation

Documentation is an integral part of ensuring the longevity of our systems, and it should not be taken lightly.

We aim to document all systems as we develop them, both through prose and [OpenAPI](https://www.openapis.org/).
However, legacy systems might not have been documented at all, or only partially. If you are knowledgeable in one
of the undocument systems, do not hesitate to file an issue or pull request to this repository.

#### Writing guidelines

The documentation should be clear, concise, and easy to understand. Everything should be written under the assumption
that the reader is unfamiliar with the system (although one can assume basic programming knowledge). It is important that
all documentation is written in english, so that everyone can understand it.

#### OpenAPI

OpenAPI is a specification for describing RESTful APIs. It allows developers to define the structure of their API, including
the endpoints, request/response formats, and authentication methods. By using OpenAPI, we can generate client libraries,
documentation, and other tools that make it easier for developers to work with our systems.

Some resources for learning more about [OpenAPI](https://www.openapis.org/) include:

- [OpenAPI Specification](https://spec.openapis.org/oas/v3.1.0)
- [OpenAPI Tools](https://openapi.tools/)
- [OpenAPI TypeScript](https://openapi-ts.dev/)
