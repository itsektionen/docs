When code is moved from one place or another is called a Push or a Pull (depending on who approves the action). When you request a Pull it is called a Pull Request, often shortened to PR.

<Steps>
<Step>
    ## "Commit" your changes
    Imagine you want to send some items via the post, the first step is placing the item inside a cardboard box.
    The code version of that is called "committing"

    To commit your code use:
    `git commit -m '<quick description of what you did>'`
    
    <CalloutExt type="details">
    (note: for our documentation, it does not really matter what you type here, `git commit -m 'waga baga bobo'` would work. HOWEVER! It is good practice to give a clear description)
    </CalloutExt>

    You can make as many commits as you want, it is often better too have two many than too few
</Step>
<Step>
    ## Pushing your changes to github
    Next we need to get all the cardboard boxes (commits) to the post office (github).
    `git push origin <docs/your branch name here>`
</Step>
<Step>
    ## Making the pull request
    This will push it to the server. If you open up your fork in the browser again, there should be a popup saying "\<branch name\> had recent changes, make a pull request?"
    with a button to create it. 

    Write a title and description about what you did. You do not need to go into every detail - we can see the code after all.

    On the rightmost side there is a place to add Labels. Click on the cogwheel and select the labels the apply.
    Usually `doc` _and_ one of `doc/edit`, `doc/new`, `doc/inaccuracy`.

    Finally: Click "Create pull request"
</Step>
</Steps>

## Congratulations!
You have now made a pull request!

You should feel proud!

We will get back to you about your pull request via Github.

We might ask for some changes to be made, or we might think of it as good to go.

## What do the responses on the pull request mean?

### "`{{User A}}` requested a review from `{{User B}}`"?

This usually means that `{{User B}}` is responsible for that part of the documentation
and should look over the code.

### "`{{User}}` reviewed"?

This is us looking over the code and giving our opinions. We are not always correct so feel free to reply if
you disagree.

If we ask for something to be changed, then you can do the following to update your code:

<Steps>
<Step>
    Simply go back to the terminal and run:

    ```bash
    git switch {{your-branch-name-here}}
    ```
    
    this makes sure you are on the correct branch

    <CalloutExt type="tip">
    If you don't remember the name of the branch, you can list all the branches with:

    ```bash
    git branch -a
    ```
    </CalloutExt>
</Step>
<Step>
Now you make the changes
</Step>
<Step>
Finally run:
```bash
git push origin {{your-branch-name-here}}
```
This sends the new changes to the server.
</Step>
</Steps>

Your pull request will automatically be updated. It might take a bit for us to see it so be patient, but if it takes more than a week, then you should message the relevant person.

### "`{{User}}` approved these changes"?

This means the person thinks it is good and can be put on the website. Sometimes the person approving
is not the one responsible, in which case it simply serves as a marker for others that the code is good.

### "LGTM"?

"Looks good to me". This means your code is good, with no extra comments.
